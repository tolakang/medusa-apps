## 4. Gotchas learned this session (all in `MEDUSA_SKILL.md` too)

- **`db:generate` on starter modules:** they have no usable snapshot, so the first generate writes a full `create table` migration. Generate once with the *unchanged* model, delete that migration but keep `.snapshot-<module>.json`, then change the model and generate again (§3).
- **Cart creation with items:** `POST /store/carts` with `items` skips `addToCartWorkflow`. Cart rules need the `createCartWorkflow`, `addToCartWorkflow`, `updateLineItemInCartWorkflow` and `completeCartWorkflow` validate hooks (§6).
- **Link cardinality:** a link without `isList` is one-to-one, and the link service refuses a second link. Adding `isList` keeps the same table (§4).
- **Signed-in user:** read `req.auth_context.actor_id`, not `app_metadata.<x>_id` (§7).
- **`medusa exec` arguments:** positional only (`pnpm seed:b2b demo-pricing`). Run seeds after the first server start.
- **Body validation:** opt-in per route. Use `.strict()` schemas and `req.validatedBody`.

## 5. How to work locally

- **Test database:** a throwaway Postgres. Wait for the *second* "ready to accept connections"; Postgres restarts once during first setup, and a database created too early is lost.
  ```bash
  podman run -d --name wholesale-check-postgres -p 55532:5432 -e POSTGRES_USER=medusa -e POSTGRES_PASSWORD=medusa -e POSTGRES_DB=postgres docker.io/library/postgres:15-alpine
  ```
- **Full gate:**
  ```bash
  DB_HOST=localhost DB_PORT=55532 DB_USERNAME=medusa DB_PASSWORD=medusa CONTAINER_CLI=podman VERIFY_DATABASE_URL=postgres://medusa:medusa@host.containers.internal:55532/wverify scripts/verify.sh wholesale/backend --image
  ```
  Then run `scripts/guard.sh wholesale`. Last result: unit 70, HTTP 36/36, image smoke `/health` 200.
- **HTTP tests:** shared B2B setup and checkout helpers are in `integration-tests/utils/b2b.ts`. Specs that put items in a cart need a company employee (`makeCompanyBuyer` in `utils/admin.ts`).
- **Podman VM:** if it stops answering (`ssh: handshake failed: EOF`), `podman machine stop && podman machine start` fixes it. That also stops the owner's booking stack, so ask first and restart their containers after.
- **Pushing over Remote Control:** the macOS Keychain prompt hangs `git push`. Push with the GitHub CLI login instead:
  ```bash
  git -c credential.helper= -c "credential.helper=!gh auth git-credential" push -u origin <branch>
  ```
- **PRs:** one branch per task, squash merge, `ci-ok` is the required check. The owner approves auto-merge per PR, so ask; if CI is already green (state CLEAN), merge directly after checking every check passed. Run the pre-merge checks every time: no PR based on the branch, base `main`.
- **CI flake:** `booking-services/backend` `search.spec.ts` sometimes misses the search index under load. Re-run the failed job.
